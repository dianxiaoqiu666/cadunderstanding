## 用户目标与当前事实

用户已认可 CAD 构件识别及其二维还原，新增目标是输出房间内部、扣除柱体等障碍后的货架/设备可用区域。用户进一步提出用大语言模型读取固定 Schema，承担可用区域判断，避免不断扩充人工语义规则。

当前真实 DXF 有 104 个源实体、8 个结构填充、9 个几何闭合面。闭合面主要是柱体和一个小房间，不足以直接证明完整店内边界。现有 Schema 固定了格式、坐标和来源，并不自动证明“这里是室内”或“所有障碍已识别”。旧项目的 Human Scope 和人工实体判断没有迁入。

## 建议流程

CAD → 现有结构化提取 → 带实体编号的平面图与精简几何 JSON → 模型语义提案 → 几何计算与验证 → 可用区域 JSON / 平面覆盖层。

1. 现有解析器继续负责坐标、单位、图层、块名、文字、拓扑和来源句柄。完整 inventory 留作追溯，不必全部塞入模型上下文。
2. 模型结合带编号的平面图、文字和几何关系，判断室内范围候选、柱/墙垛等障碍候选、门口及不确定项。多模态输入是否比仅 JSON 有效，必须用实际标注样本对照验证。
3. 模型优先引用已有实体、顶点和候选区域 ID。对于断口，返回可追溯的端点连接提案、理由及缺失证据，不直接修改原 CAD，也不凭空生成最终精确坐标。
4. 程序验证来源哈希、ID 是否存在、环闭合、自交、孔洞、范围关系，再用 Shapely 计算室内范围扣除障碍和退让后的区域；面积、孔洞和多块区域由程序输出。
5. 整件货架/设备占地通过包含与碰撞检查后才具备几何摆放条件。墙厚、开合范围等缺失时保留待核实状态。高度不足影响 3D 构建，不直接否定明确的二维区域。

## 模型提案与正式结果分开

已新增独立 SemanticProposal 契约，包含 source_sha256、evidence_sha256、类别提案、室内边界/孔洞顶点、补边声明、关系、证据及未确定事项。返回内容附在 CadPackage.enrichment；坐标由引用的源顶点恢复，原构件和正式 usable_area 保留。

来源应明确区分 CAD 显式事实、模型推断和用户确认。模型判断不能写成 SOURCE_BOUND_USER。模型自报置信度不能代替室内真实性或几何验证。开始阶段以候选覆盖层展示模型推断；经样本验收后，再确定哪些证据条件可支持自动采纳。没有足够闭合边界证据的情况允许返回未确定。

固定 Schema 的作用是约束可解析的格式、类型和引用方式，不能保证模型填入的内容语义正确。这一限制也见 [Google 官方结构化输出说明](https://ai.google.dev/gemini-api/docs/generate-content/structured-output?hl=en) 的 Validation 部分，核对日期 2026-09-09；这不代表已经选择 Gemini 作为供应商。

## 已有实现与验证

已加入 usable_area 契约、室内区域求差、柱体/填充/孔洞排除、独立区域和面积输出、退让距离、墙线屏障与整件占地校验；API、CLI、下载和网页圈定入口已写入工作区。它们可作为后续模型输出的执行和验证层。

2026-09-09 自动测试：39 项通过（原 20 项 + 新增 19 项），2 个既有依赖弃用警告。证据：outputs/usable-area-tests.xml。包含原始真实 CAD 构件与备份一致性，以及凹形范围、圆柱保守占地、内部孔洞、障碍重叠、整件占地越界/穿墙、未知墙宽、单位换算和空区域。

真实 CAD 中测试用的 600 m² 矩形只是内存中的合成测试范围，用于验证 8 个真实填充的扣除；它没有保存为生产范围，也不是已确认室内面积。
